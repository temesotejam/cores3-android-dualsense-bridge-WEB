# CoreS3 Android DualSense Bridge

> LG style3 と PS5 DualSense を使って、M5Stack CoreS3 から PCA9685 と VESC を動かすための、かなり端末依存な無線コントロール構成です。

## 重要

このプロジェクトは **汎用の DualSense 対応コントローラブリッジではありません**。

2026年8月3日時点では、実運用の前提は次の 1 台です。

- スマホ: **LG style3**
- ブラウザ: **Android 版 Google Chrome**
- コントローラ: **PS5 DualSense**
- 受け側: **M5Stack CoreS3**

特に Android Chrome の Gamepad API の見え方が素直ではなく、このスマホでは **右スティックと L2/R2 の取り扱いが非常に特殊** でした。  
そのため、README の後半に「何が起こるか」「どうすれば回避できるか」「何をすると失敗しやすいか」を詳しく残しています。

別のスマホでそのまま動く前提では使わないでください。

## 今の構成

```text
PS5 DualSense
  │ Bluetooth
  ▼
LG style3 + Android Chrome
  │ Web UI + Gamepad API + WebSocket
  ▼
M5Stack CoreS3
  ├─ I2C → PCA9685
  │    ├─ CH0: 左翼サーボ
  │    ├─ CH1: 右翼サーボ
  │    └─ CH2: 左右向きサーボ
  └─ UART → VESC
       └─ Duty 指令
```

CoreS3 が自前で Wi-Fi アクセスポイントを立て、スマホはそこへ直接接続します。  
スマホは「入力を拾って送るだけ」で、最終的な停止や出力ゼロ化は CoreS3 側が持ちます。

## 今できること

- CoreS3 が Wi-Fi AP `CoreS3-Control` を立てる
- `http://192.168.4.1` に日本語の操作ページを出す
- Android Chrome の Gamepad API から DualSense 入力を取得する
- WebSocket で CoreS3 へ約 30 Hz で送る
- PCA9685 で 3 つのサーボを駆動する
- VESC に UART で Duty を送る
- サーボ角度の上下限を Web UI から保存する
- 入力断、非常停止、L1 非押下時に安全側へ倒す

## 制御割り当て

今の操作割り当ては次です。

| 入力 | 出力 |
| --- | --- |
| 左スティック上下 | 左翼サーボ |
| 右スティック上下 | 右翼サーボ |
| L2 | 左向きサーボ |
| R2 | 右向きサーボ |
| 十字キー 上/下 | モータ速度の増減 |
| L1 | デッドマン有効 |
| PS | 非常停止 |

補足:

- 十字キーの上/下は長押しで連続変化します
- **L1 を押している間だけ** モータ速度変更が有効です
- **L1 を離すとモータ速度は 0 に戻ります**
- 左右向きサーボは、L2 と R2 が同時に入ったときでも急に最大へ飛ばないよう、今の指令に近い側を優先します
- さらに左右向きサーボにはレート制限を入れています

## 安全動作

安全判断は CoreS3 側で行います。

| 条件 | 動作 |
| --- | --- |
| L1 を押していない | 全出力ゼロ |
| PS または UI の非常停止 | 停止ラッチ |
| 停止ラッチ中 | L1 を一度離すまで再開しない |
| スマホ切断 | 全出力ゼロ |
| WebSocket 断 | 全出力ゼロ |
| 一定時間コマンドなし | 全出力ゼロ |
| 不正なパケット | 破棄して全出力ゼロ |

また、LG style3 固有の変な初期入力対策として、右翼入力は **一度ゼロ近傍を確認するまで無視** します。

## 配線

### CoreS3 → PCA9685

- CoreS3 Port A
  - SDA: `GPIO2`
  - SCL: `GPIO1`
- PCA9685 address: `0x40`
- PWM frequency: `50 Hz`

### PCA9685 チャンネル割り当て

- `CH0`: 左翼
- `CH1`: 右翼
- `CH2`: 左右向き

### CoreS3 → VESC

- CoreS3 Port C
  - TX: `GPIO17`
  - RX: `GPIO18`
- UART baud: `115200`

### 配線時の注意

- **CoreS3 と VESC の GND は必ず共通化** してください
- TX/RX は交差です
  - `CoreS3 TX → VESC RX`
  - `CoreS3 RX ← VESC TX`
- PCA9685 のサーボ電源は、CoreS3 本体の 5V 系と電流設計を分けて考えてください
- サーボやモータをつないだまま最初の入力確認を始めないほうが安全です

## Web UI

操作ページには次があります。

- 接続開始 / 非常停止 / 停止解除
- 入力プロファイル選択
- 左翼 / 右翼 / 左右向き / モータ速度のバー表示
- 数値表示
- サーボ上下限設定
- 生入力ログ表示

サーボの上下限は Web UI から保存でき、**電源を切っても保持** されます。  
保存先は CoreS3 の NVS です。

## PS5 DualSense と LG style3 で苦労した点

ここがいちばん重要です。

### 1. Android で見える入力が「普通の gamepad」ではない

このスマホでは、Chrome の Gamepad API 上で DualSense の入力が素直に見えませんでした。

特に問題になったのは次です。

- `L1` が一般的な `B4` ではなく **`B2` 扱い**
- `L2 / R2` が素直な trigger ではなく、**軸とボタンが混ざって見える**
- `右スティック` が通常の軸として安定して見えず、最終的に **`pad.buttons[7]` 由来の値** を使う形に落ち着いた
- 起動直後に **右翼だけ 100 が入る** ことがある

つまり、一般的な「DualSense はこう見えるはず」という前提で実装すると高確率で壊れます。

### 2. 以前うまくいっていた割り当てを不用意に変えると、すぐ壊れる

途中で次のようなことが起きました。

- `L1` を押していないのにモータ速度が変わる
- `L1` と `L2` が同じ入力に見える
- `L2 / R2` が 0 / 100 の二値に見える
- `右スティック` が反応せず、`L2` を動かすと右翼が動く
- `右翼` が常に `100` から始まる

原因は多くの場合、**軸番号を一般論で決め打ちしたこと** です。

### 3. 今回の回避策

今回の構成では、LG style3 向けに次を前提にしています。

- `L1 = B2`
- `L2 = A2 + B4`
- `R2 = A3 + B5`
- `右翼 = pad.buttons[7]` から作る疑似軸

さらに起動直後の誤反応対策として、

- `右翼` は **一度ゼロ近傍に戻るまで 0 扱い**

にしています。

これにより、最初に `100` が見えても、そのまま機体へ出ないようにしています。

## 失敗しやすいこと

### 1. 別のスマホでそのまま使う

たぶん壊れます。

症状の例:

- ボタンが違う入力として反応する
- スティックとトリガーが入れ替わる
- 右スティックだけ反応しない
- 初期値が飛ぶ

### 2. Android アプリでの実測結果を見ずに、Gamepad の一般的な配列を信じる

これも壊れやすいです。

今回の作業では、別リポジトリの診断アプリ  
[`controller-input-diagnostics`](https://github.com/temesotejam/controller-input-diagnostics)  
を使って、生の入力をかなり細かく見直しました。

### 3. 「認識方式」を変えて初期値問題を直そうとする

今回の `右翼が最初だけ 100` 問題は、入力の意味づけを変えるのではなく、

- **最初はゼロ付近を確認するまで聞かない**

という情報処理で直しました。

ここを無理に別軸へ置き換えると、せっかく合っていた他の部分まで壊れやすいです。

### 4. サーボやモータをつないだままマッピング調整をする

危険です。

この端末では入力の初期飛びや、想定外の重なりが実際にありました。  
最初の確認は必ず軽負荷または無負荷で行ってください。

## 失敗したときの見方

症状ごとの見方を残します。

### 右翼だけ変

- まず起動直後だけ `100` に飛んでいないか確認
- 一度中立に戻したあとで正常になるなら、初期値問題の可能性が高い
- `右スティック` と `L2/R2` を同時に触って、混線していないか確認

### L2 / R2 が変

- 0 / 100 しか出ないなら、軸ではなくボタンだけを見ている可能性がある
- スティックを触ったときにサーボが動くなら、軸割り当てが壊れている

### L1 が変

- L1 を押しても有効にならないなら、まず `B2` 前提を疑う
- 一般的な `B4` 前提へ戻すと、このスマホでは壊れる可能性が高い

## この構成を他端末へ持っていくなら

そのまま流用しないでください。  
最低でも次をやってからです。

1. Android 側で生の軸とボタンを診断する
2. L1, L2, R2, 右スティックが何として見えるかを記録する
3. 起動直後に変な初期値が出るか確認する
4. その端末用のプロファイルを追加する

つまり、この README の内容は「DualSense 一般論」ではなく、
**LG style3 で動いた具体例** です。
